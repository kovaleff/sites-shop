# Quickstart: Проверка административных разделов

**Feature**: `002-orchid-admin-models` | **Date**: 2026-10-28

Пошаговая проверка того, что все сущности биржи доступны в панели, меню содержит ссылки, а правила редактирования и read-only-разделы соблюдаются.

## Prerequisites

- PHP 8.3 и зависимости установлены (`composer install`).
- Настроено подключение к базе данных, миграции выполнены (`php artisan migrate`).
- Ассеты Orchid опубликованы (`php artisan orchid:publish`), каталог `public/vendor/orchid` существует.
- Есть администратор `admin@example.com` с паролем из локальной среды.
- Приложение запущено: `php artisan serve`.

## 1. Выдать новые права существующему администратору

Новые администраторы получают все права автоматически. Для уже созданного администратора выполните разовое обновление:

```bash
php artisan tinker --execute 'App\Models\User::where("email", "admin@example.com")->first()->forceFill(["permissions" => Orchid\Support\Facades\Dashboard::getAllowAllPermission()->toArray()])->save();'
```

Проверка:

```bash
php artisan tinker --execute 'echo json_encode(App\Models\User::where("email", "admin@example.com")->first()->permissions);'
```

Ожидается, что в JSON присутствуют ключи `platform.marketplace.sites`, `platform.marketplace.categories`, `platform.marketplace.conversations`, `platform.marketplace.messages`, `platform.marketplace.payments` со значением `true`.

## 2. Проверить маршруты

```bash
php artisan route:list --path=marketplace
```

Ожидается 11 маршрутов: списки и карточки шести разделов (у тематик два маршрута формы — создание и редактирование).

## 3. Проверить меню и навигацию

1. Откройте `/admin` и войдите под администратором.
2. Убедитесь, что в меню есть группа «Биржа» с шестью пунктами: Пользователи, Тематики, Объявления, Диалоги, Сообщения, Платежи.
3. Поочерёдно откройте каждый пункт.

**Ожидаемый результат**: каждый пункт открывает свой список, активный пункт выделен, ошибок нет.

## 4. Проверить объявления

Подготовьте данные в локальной среде, если их нет:

```bash
php artisan tinker --execute '$u = App\Models\User::first(); App\Models\Site::factory()->count(3)->for($u)->create();'
```

1. Откройте «Биржа → Объявления».
2. Примените фильтр по домену, статусу, диапазону цены и диапазону дохода.
3. Откройте карточку объявления.
4. Измените название, цену и набор тематик; сохраните.
5. Переключите «Подтверждено» и сохраните.
6. Попробуйте недопустимый переход статуса (например, из «Продан» в «Активен»).
7. Убедитесь, что имя файла проверки и дата «оплачено до» отображаются, но не редактируются.

**Ожидаемый результат**:

- фильтры сужают список и сохраняются в адресе;
- изменения коммерческих полей сохраняются;
- подтверждение владения сохраняется и сразу видно в списке;
- недопустимый переход отклоняется с сообщением, статус не меняется;
- служебные поля недоступны для изменения;
- публичная видимость соответствует статусу и дате «оплачено до».

## 5. Проверить тематики

1. Откройте «Биржа → Тематики».
2. Создайте тематику с уникальным названием.
3. Переименуйте её и убедитесь, что публичный идентификатор не изменился.
4. Попробуйте удалить тематику, связанную с объявлением.
5. Создайте неиспользуемую тематику и удалите её.

**Ожидаемый результат**:

- создание и переименование работают;
- публичный идентификатор стабилен;
- удаление используемой тематики отклоняется с объяснением;
- неиспользуемая тематика удаляется.

## 6. Проверить read-only-разделы

Для проверки нужны диалог, сообщения и платёж. Создайте их в локальной среде через фабрики или используйте существующие данные.

1. Откройте «Биржа → Диалоги», выберите диалог.
2. Убедитесь, что видны участники, объявление и история сообщений, но нет кнопок отправки, редактирования и удаления.
3. Откройте «Биржа → Сообщения», примените фильтры по диалогу, отправителю и прочтению.
4. Откройте «Биржа → Платежи», примените фильтры по статусу, объявлению, плательщику и дате.
5. Выполните POST на несуществующее действие вручную (например, через форму разработчика) и убедитесь, что возвращается `405` — экран действие не принимает.

**Ожидаемый результат**: все три раздела доступны только для просмотра; POST-действия отсутствуют.

## 7. Проверить карточку пользователя

1. Откройте «Биржа → Пользователи» и выберите пользователя с объявлениями.
2. Прокрутите карточку до блоков «Объявления», «Диалоги», «Платежи».
3. Убедитесь, что отображаются последние записи и ссылки на карточки.
4. Убедитесь, что действие удаления пользователя отсутствует.

**Ожидаемый результат**: связанные данные видны, удаление недоступно.

## 8. Проверить разграничение доступа

1. Создайте пользователя с правом только `platform.marketplace.payments`.
2. Войдите под ним.
3. Убедитесь, что в меню «Биржа» виден только пункт «Платежи».
4. Попробуйте открыть `/admin/marketplace/sites` напрямую.

**Ожидаемый результат**: доступен только разрешённый раздел; прямой переход в запрещённый возвращает `403`.

## 9. Автоматические проверки

```bash
php artisan test --compact --filter=Orchid
```

Ожидается: все тесты административных разделов проходят.

Полный прогон:

```bash
php artisan test --compact
```

Форматирование:

```bash
vendor/bin/pint --dirty --format agent
```

## Troubleshooting

| Симптом | Решение |
|---|---|
| Пункты меню не появились | Проверьте права администратора (шаг 1) и `php artisan optimize:clear`. |
| `403` при открытии раздела | У пользователя нет соответствующего права; выдайте его через «Пользователи» или роль. |
| `405` на действии сохранения | Действие не объявлено в экране (read-only-раздел); проверьте имя метода и маршрут. |
| Стили панели не загружаются | Выполните `php artisan orchid:publish` и проверьте `public/vendor/orchid`. |
| Ошибка `Unable to locate file in Vite manifest` | Административные экраны используют ассеты Orchid; для публичной части выполните `npm run build`. |
