# Contract: Данные каталога и сессии

**Feature**: `003-catalog-home-page` | **Date**: 2026-10-28 | **Тип**: внутренний клиентский контракт, воспроизводящий ожидаемый HTTP API

Фича фронтендовая: реальные эндпоинты появятся в отдельной фиче. Контракт ниже описывает **форму запроса и ответа**, которую обязан соблюдать мок-сервис, чтобы замена на HTTP была локальной и не затрагивала компоненты.

Соглашения:
- Все денежные значения — целые числа в рублях, без копеек.
- Все даты — ISO 8601 UTC (`2026-10-01T12:00:00Z`).
- Имена полей — `camelCase`.
- Ошибки — объект `{ message: string }`; UI показывает `message` или общий текст, если сообщения нет.

## 1. `fetchListings(query)` → `CatalogResult`

**Логический HTTP-эквивалент**: `GET /api/catalog`

### Запрос

| Параметр | Тип | Обязателен | По умолчанию | Описание |
|---|---|---|---|---|
| `price_min` | integer ≥ 0 | нет | `0` | Нижняя граница цены, включительно |
| `price_max` | integer ≥ 0 | нет | `10000000` | Верхняя граница цены, включительно; `10000000` = «и выше» |
| `income_min` | integer ≥ 0 | нет | `0` | Нижняя граница дохода, включительно |
| `income_max` | integer ≥ 0 | нет | `1000000` | Верхняя граница дохода, включительно; `1000000` = «и выше» |
| `zones` | string (CSV) | нет | все | Зоны через запятую: `ru,com`; пустая строка = все зоны |
| `verified` | `0` \| `1` | нет | `0` | `1` — только проверенные |
| `page` | integer ≥ 1 | нет | `1` | Номер страницы |
| `per_page` | integer | нет | `25` | Фиксирован 25; другие значения игнорируются |
| `sort` | `newest` | нет | `newest` | Единственный поддерживаемый порядок |

### Успешный ответ

```json
{
  "items": [
    {
      "id": "lst_0001",
      "title": "Сервис доставки фермерских продуктов",
      "domain": "ferma-dostavka.ru",
      "domainZone": "ru",
      "description": "Действующий проект с постоянными клиентами и настроенной рекламой.",
      "price": 1250000,
      "monthlyIncome": 85000,
      "status": "active",
      "isVerified": true,
      "faviconUrl": null,
      "publishedAt": "2026-10-21T09:30:00Z"
    }
  ],
  "meta": {
    "page": 1,
    "perPage": 25,
    "total": 60,
    "lastPage": 3,
    "from": 1,
    "to": 25
  }
}
```

### Ошибка

```json
{ "message": "Не удалось загрузить каталог" }
```

### Обязательные правила реализации

1. **Видимость**: лоты с `isPublic: false` в фикстурах и любые лоты со `status !== 'active'` исключаются до применения фильтров и не входят в `meta.total`.
2. **Фильтр цены**: `price_min ⩽ price ⩽ price_max`, кроме случая `price_max === 10000000` — тогда верхняя граница не ограничивает.
3. **Фильтр дохода**: `income_min ⩽ monthlyIncome ⩽ income_max`, кроме случая `income_max === 1000000` — тогда верхняя граница не ограничивает.
4. **Фильтр зон**: `zones` непустой → `domainZone` входит в набор; внутри фильтра логика «ИЛИ», с остальными фильтрами — «И». Пустой `zones` → ограничения нет, лоты без зоны тоже видны. Выбор всех конкретных зон не эквивалентен пустому `zones`: лоты с `domainZone: null` в этом случае не показываются.
5. **Фильтр проверки**: `verified = 1` → только `isVerified === true`.
6. **Сортировка**: `publishedAt` по убыванию; при равенстве — `id` по возрастанию (детерминированно, без дублей).
7. **Пагинация**: `slice((page - 1) * 25, page * 25)`; `lastPage = max(1, ceil(total / 25))`.
8. **Страница за пределами**: `items = []`, `meta.from = null`, `meta.to = null`, `meta.total` и `meta.lastPage` корректны; ошибка не возвращается.
9. **Невалидные параметры** (отрицательные, нечисловые, `min > max`, неизвестные зоны) нормализуются до применения, ответ не содержит ошибки.
10. **Задержка**: 250 мс по умолчанию, 2000 мс в сценарии `slow`, чтобы состояние загрузки было наблюдаемым.
11. **Сценарии**: `empty` → `items = []`, `total = 0`; `error` → промис отклоняется с `{ message: "Не удалось загрузить каталог" }`.
12. **Иммутабельность**: сервис возвращает копии объектов; мутация результата в UI не должна менять фикстуры.

### JS-сигнатура

```js
/**
 * @param {{
 *   priceMin?: number,
 *   priceMax?: number,
 *   incomeMin?: number,
 *   incomeMax?: number,
 *   zones?: string[],
 *   verifiedOnly?: boolean,
 *   page?: number,
 *   perPage?: number,
 *   sort?: 'newest',
 * }} query
 * @returns {Promise<{
 *   items: Array<object>,
 *   meta: { page: number, perPage: number, total: number, lastPage: number, from: number|null, to: number|null },
 * }>}
 */
export function fetchListings(query) {}
```

`fetchListings` принимает **camelCase**-объект; преобразование в snake_case-параметры HTTP выполняется внутри сервиса при переходе на реальный API.

## 2. `fetchZones()` → `DomainZone[]`

**Логический HTTP-эквивалент**: `GET /api/catalog/zones`

### Ответ

```json
{
  "items": [
    { "value": "ru", "label": ".ru", "count": 24 },
    { "value": "com", "label": ".com", "count": 21 },
    { "value": "de", "label": ".de", "count": 12 }
  ]
}
```

### Правила

1. `value` — латиница в нижнем регистре без точки; `label` — с ведущей точкой.
2. Список строится по публичным лотам, поэтому скрытые лоты не увеличивают `count`; `mocks/zones.js` — только начальный набор на случай ошибки загрузки (FR-010).
3. Новые зоны, появившиеся в данных, автоматически попадают в ответ; порядок: известные (`ru`, `com`, `de`), затем алфавитный.
4. Лоты с `domainZone: null` в ответ не входят и не учитываются в `count`; они остаются видимыми только при варианте «Все зоны» (FR-011).
5. Сумма `count` по зонам может быть меньше `total` публичных лотов — ровно на число лотов без распознанной зоны. Для набора фикстур: 24 + 21 + 12 = 57 из 60.
6. Ошибка → `{ message: "Не удалось загрузить список зон" }`; панель фильтров остаётся работоспособной с зонами по умолчанию из `catalogConfig`.

### JS-сигнатура

```js
/**
 * @returns {Promise<Array<{ value: string, label: string, count: number }>>}
 */
export function fetchZones() {}
```

## 3. Сессия

### 3.1 `fetchSession()` → `Session`

**Логический HTTP-эквивалент**: `GET /api/session`

```json
{ "data": { "authenticated": false, "user": null } }
```

```json
{
  "data": {
    "authenticated": true,
    "user": {
      "id": "usr_demo",
      "displayName": "Демо Покупатель",
      "avatarUrl": null,
      "provider": "vk"
    }
  }
}
```

**Правила**:
- При наличии валидного `localStorage.catalog:session` возвращается сохранённый пользователь.
- Повреждённая запись (`JSON.parse` бросает исключение, отсутствует `id`) → запись удаляется, возвращается гость, ошибка не показывается.
- Сетевой ошибки у мока нет; реальный API вернёт `{ message }` при 5xx.

### 3.2 `login(provider)` → `Session`

**Логический HTTP-эквивалент**: `POST /api/auth/{provider}/login` (`provider: 'vk' | 'yandex'`)

**Правила**:
1. Задержка ~600 мс, затем успех; результат — `authenticated: true`, `user.provider = provider`.
2. Успех сохраняется в `localStorage.catalog:session` и в сторе `session`.
3. Сценарий `auth-error` → промис отклоняется с `{ message: "Не удалось войти через VK ID. Попробуйте ещё раз." }` (текст зависит от провайдера).
4. При ошибке навигация не выполняется, фильтры и страница каталога сохраняются, показывается тост.
5. Повторный вызов во время выполнения игнорируется: кнопки блокируются на время `isLoggingIn`.
6. `login` не меняет `catalog`-стор ни при успехе, ни при ошибке.

### 3.3 `logout()`

**Логический HTTP-эквивалент**: `POST /api/auth/logout`

**Правила**: очищает `localStorage.catalog:session` и стор; каталог остаётся доступным; навигация не выполняется.

### JS-сигнатуры

```js
/** @returns {Promise<{ authenticated: boolean, user: object|null }>} */
export function fetchSession() {}

/** @param {'vk'|'yandex'} provider @returns {Promise<{ authenticated: true, user: object }>} */
export function login(provider) {}

/** @returns {Promise<void>} */
export function logout() {}
```

## 4. Форматирование (потребитель контракта)

| Функция | Вход | Выход |
|---|---|---|
| `formatRub(value)` | `1250000` | `1 200 000 ₽` (пробелы неразрывные) |
| `formatRubMonthly(value)` | `85000` | `85 000 ₽/мес` |
| `formatCount(value)` | `60` | `60` |
| `formatDate(iso)` | `2026-10-21T09:30:00Z` | `21.10.2026` |

**Правила**: `null`, `undefined`, `NaN`, отрицательные значения → `0 ₽` (не «пусто» и не «−»); очень большие значения не обрезаются и не переводятся в компактную нотацию.
