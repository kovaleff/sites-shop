# Data Model: Публичная главная страница с каталогом сайтов

**Feature**: `003-catalog-home-page` | **Date**: 2026-10-28

Модель описывает клиентские структуры данных фронтенда и контракт мок-сервиса. Серверных таблиц, миграций и Eloquent-моделей эта фича не добавляет: источник данных — фикстуры в `resources/js/mocks`, повторяющие ожидаемый ответ API.

Обозначения: `?` — поле может быть `null`, `→` — производное значение, `⩽` — включительная граница.

---

## 1. Публичный лот (`Listing`)

Продаваемый сайт в публичном представлении. Соответствует сущности «Публичный лот» из спецификации и карточке каталога.

| Поле | Тип | Обязательность | Правила |
|---|---|---|---|
| `id` | string | да | Уникальный идентификатор в пределах выдачи; используется как `key` в списке |
| `title` | string | да | 1…120 символов; в карточке обрезается до 2 строк |
| `domain` | string | да | Полный домен без схемы и пути, например `example.ru`; в карточке обрезается по ширине с сохранением читаемости |
| `domainZone` | string \| null | нет | Одна из зон каталога (`ru`, `com`, `de`) либо `null`, если зона не распознана |
| `description` | string \| null | нет | До 300 символов; пустая строка и `null` равнозначны отсутствию описания |
| `price` | integer | да | Рубли, `≥ 0`, без копеек |
| `monthlyIncome` | integer | да | Рубли в месяц, `≥ 0` |
| `status` | `'active'` | да | Публичный каталог отдаёт только `active`; поле нужно для отображения статуса в карточке |
| `isVerified` | boolean | да | Признак проверки продавца/сайта |
| `faviconUrl` | string \| null | нет | Абсолютный или относительный URL; `null` → текстовая заглушка из первой буквы домена |
| `publishedAt` | string (ISO 8601) | да | Используется для сортировки «сначала новые» и отображения даты публикации |

**Производные значения** (вычисляются в `lib/format.js`, не хранятся):
- `formattedPrice` → `«1 200 000 ₽»` через `Intl.NumberFormat('ru-RU')`.
- `formattedIncome` → `«85 000 ₽/мес»`.
- `zoneLabel` → `«.ru»`, `«.com»`, `«.de»`; при `domainZone === null` → `«зона не определена»`.
- `faviconFallback` → первая буква `domain` в верхнем регистре.

**Правила видимости** (FR-017, SC-003):
- В выдачу попадают только лоты со `status === 'active'` и действующим признаком публичности, который в мок-слое выражен полем `isPublic` у фикстуры и не отдаётся клиенту.
- Лоты с `isPublic: false` фильтруются **до** применения пользовательских фильтров и не влияют на `total`.
- Устаревшие/скрытые лоты не должны появляться даже при прямом переходе на страницу за пределами диапазона.

**Инварианты**:
- `price ≥ 0`, `monthlyIncome ≥ 0`.
- `domain` уникален в пределах фикстур — защита от дублей при пагинации (SC-004).
- Сортировка по умолчанию: `publishedAt` по убыванию, при равенстве — по `id` по возрастанию (детерминированный порядок без дублей и пропусков).

## 2. Доменная зона (`DomainZone`)

| Поле | Тип | Правила |
|---|---|---|
| `value` | string | `ru`, `com`, `de`; латиница в нижнем регистре, без ведущей точки |
| `label` | string | Отображаемое значение с ведущей точкой: `.ru`, `.com`, `.de` |
| `count` | integer | Количество публичных лотов в зоне (для подсказки; не фильтруется) |

**Правила**:
- Список зон формируется из данных каталога, а не хардкодится в компоненте (FR-010, edge case «появилась новая зона»). `mocks/zones.js` хранит только начальный набор для случая ошибки загрузки.
- Неизвестные зоны, пришедшие в URL, отбрасываются при нормализации.
- Лоты с `domainZone === null` видны только при варианте «Все зоны» (пустой `zones`); выбор всех конкретных зон не делает их видимыми (FR-011).
- Порядок отображения: сначала известные зоны в порядке `ru`, `com`, `de`, затем новые — по алфавиту.

## 3. Состояние фильтров (`CatalogFiltersState`)

| Поле | Тип | По умолчанию | Правила |
|---|---|---|---|
| `priceMin` | integer | `0` | `0 ⩽ priceMin ⩽ priceMax ⩽ 10 000 000` |
| `priceMax` | integer | `10 000 000` | Значение, равное максимуму, означает «и выше» |
| `incomeMin` | integer | `0` | `0 ⩽ incomeMin ⩽ incomeMax ⩽ 1 000 000` |
| `incomeMax` | integer | `1 000 000` | Значение, равное максимуму, означает «и выше» |
| `zones` | string[] | `[]` | Пустой массив = все зоны; значения только из списка зон |
| `verifiedOnly` | boolean | `false` | `true` → только `isVerified === true` |

**Два экземпляра состояния**:
- `draft` — то, что пользователь двигает в панели; в URL не попадает, запросы не вызывает.
- `applied` — то, что реально применено и определяет выдачу; сериализуется в URL.

**Правила перехода**:
1. `apply()` копирует `draft` → `applied`, сбрасывает `page` в `1`, пишет query в URL, запускает загрузку.
2. `reset()` возвращает и `draft`, и `applied` к значениям по умолчанию, `page = 1`, очищает query, перезагружает список.
3. Изменение `draft` не меняет `applied` и не запускает запрос (FR-014, US1-7).
4. `draft` пересоздаётся из `applied` после каждого применения и после гидратации из URL, чтобы «несохранённые» правки не переживали сброс.
5. Ограничение ползунков: `priceMin` не может превысить `priceMax` и наоборот; при попытке пересечения вторая ручка останавливается на значении первой (FR-008, US1-12).

**Счётчик активных фильтров** (`activeCount`, FR-016) — число фильтров, значение которых отличается от значения по умолчанию:

| Фильтр | Считается активным, когда |
|---|---|
| Цена | `priceMin !== 0` или `priceMax !== 10 000 000` |
| Доход | `incomeMin !== 0` или `incomeMax !== 1 000 000` |
| Доменные зоны | `zones.length > 0` |
| Проверен | `verifiedOnly === true` |

Диапазон `0…0` у цены считается активным (значение отличается от границ), это осознанно: пользователь сузил выдачу.

## 4. Состояние каталога (`CatalogState`)

| Поле | Тип | Правила |
|---|---|---|
| `applied` | `CatalogFiltersState` | См. раздел 3 |
| `page` | integer | `≥ 1`, по умолчанию `1` |
| `perPage` | integer | Фиксировано `25`, в URL не передаётся |
| `items` | `Listing[]` | Не более `perPage` |
| `total` | integer | Общее число лотов под применённые фильтры (все страницы) |
| `lastPage` | integer | `max(1, ceil(total / perPage))` |
| `status` | `'idle' \| 'loading' \| 'success' \| 'error'` | Управляет отображением скелетонов/списка/ошибки |
| `error` | string \| null | Текст ошибки для `CatalogErrorState` |
| `requestId` | integer | Монотонный счётчик; ответ применяется только при совпадении с текущим |

**Переходы состояний**:

```text
idle ──load()──▶ loading ──успех──▶ success
                    │
                    ├──ошибка──▶ error ──retry()──▶ loading
                    │
                    └──новый load() (requestId++) ──▶ loading (старый ответ игнорируется)
```

**Правила**:
- `load()` увеличивает `requestId`; ответ с меньшим `requestId` отбрасывается без изменения `items` (FR-036).
- При смене применённых фильтров `page` принудительно становится `1` (FR-015).
- При смене страницы фильтры не меняются, а представление прокручивается к началу списка (FR-024).
- `goToPage(page)` клампит значение в `1…lastPage` для навигации по пагинации; `setPageFromUrl(page)` не клампит, а возвращает флаг `outOfRange`; если `total > 0` и `page > lastPage`, вызывающий код делает `router.replace` на `lastPage` и повторную загрузку, ошибка не показывается (edge case «страница за пределами»).
- `total === 0` и активных фильтров нет → пустое состояние «Предложений пока нет»; `total === 0` при активных фильтрах → «Ничего не найдено» + сброс (FR-025).
- Ошибка не изменяет `applied` и `draft` (FR-026).
- `perPage` всегда `25`; значение не настраивается из UI (FR-018).

## 5. Результат каталога (`CatalogResult`)

| Поле | Тип | Правила |
|---|---|---|
| `items` | `Listing[]` | Лоты текущей страницы |
| `meta.page` | integer | Запрошенная страница (после нормализации) |
| `meta.perPage` | integer | `25` |
| `meta.total` | integer | Общее число подходящих публичных лотов |
| `meta.lastPage` | integer | `≥ 1` |
| `meta.from` | integer \| null | Индекс первого лота страницы (`1`-based) или `null` при пустой выдаче |
| `meta.to` | integer \| null | Индекс последнего лота страницы или `null` |

**Правила**:
- Счётчик «Показано X из Y» использует `items.length` и `meta.total` (FR-019).
- Пагинация строится по `meta.lastPage`; переходы за диапазон недоступны (FR-023).
- Дубли и пропуски исключены детерминированной сортировкой и `slice` по `(page - 1) * perPage` (SC-004).
- Пустая страница: `items = []`, `from = null`, `to = null`, `total` сохраняется.

## 6. Сессия посетителя (`Session`)

| Поле | Тип | Правила |
|---|---|---|
| `authenticated` | boolean | `false` по умолчанию |
| `user.id` | string | Только при `authenticated = true` |
| `user.displayName` | string | Отображается в меню аватара |
| `user.avatarUrl` | string \| null | `null` → аватар из инициалов |
| `user.provider` | `'vk' \| 'yandex'` | Провайдер последнего успешного входа |
| `isLoggingIn` | boolean | Управляет блокировкой кнопок и индикатором |
| `authError` | string \| null | Текст ошибки для тоста |

**Правила**:
- Каталог доступен при `authenticated = false` (FR-035).
- `login('vk' | 'yandex')` в мок-слое: задержка ~600 мс → успех с фикстурой пользователя → запись в `localStorage.catalog:session`.
- Сценарий `auth-error`: промис отклоняется, `authError` заполняется, навигация не выполняется, фильтры сохраняются (SC-014).
- Повреждённый или устаревший `localStorage.catalog:session` → сессия сбрасывается в гостя без ошибки.
- `logout()` очищает стор и `localStorage`.
- Аватар заменяет кнопки входа (FR-005); переход в профиль в этой итерации не реализуется — пункт меню показывает тост.

## 7. Настройки каталога (`CatalogConfig`)

| Константа | Значение | Назначение |
|---|---|---|
| `PAGE_SIZE` | `25` | Размер страницы (FR-018) |
| `PRICE_BOUNDS` | `{ min: 0, max: 10_000_000, step: 50_000 }` | Фиксированные границы цены |
| `INCOME_BOUNDS` | `{ min: 0, max: 1_000_000, step: 5_000 }` | Фиксированные границы дохода |
| `DEFAULT_SORT` | `'newest'` | Единственный порядок сортировки |
| `MOCK_LATENCY_MS` | `250` | Имитация сети; `slow`-сценарий — `2000` |
| `MAX_PAGE_LINKS` | `5` | Количество номеров страниц в пагинации |

**Правила**:
- Границы не могут быть отрицательными; `max > min`; `step` делит диапазон без остатка.
- Значения вынесены в модуль, чтобы будущий API мог заменить их ответом `/catalog/filters` без правок компонентов.

## 8. Мок-фикстуры (`resources/js/mocks`)

Состав набора: 63 фикстуры, из них 3 скрытых (`isPublic: false`) → 60 публичных лотов, то есть 3 страницы по 25 с остатком 10 на последней.

| Признак | Распределение | Что проверяет |
|---|---|---|
| Доменные зоны (публичные 60) | 24 × `ru`, 21 × `com`, 12 × `de`, 3 × `null` | Фильтр зон, «Все зоны», лоты без зоны |
| Цена | от `0` до `18 000 000` (2 лота выше верхней границы) | Нулевая цена, «и выше» на максимуме (SC-018) |
| Доход | от `0` до `1 500 000` (2 лота выше верхней границы) | Нулевой доход, «и выше» |
| Проверка | 38 проверенных, 25 непроверенных | `Switch` «Проверен» |
| Публичность | 60 публичных, 3 скрытых | Видимость (SC-003) |
| Описание | 2 лота без описания, 1 с пустой строкой | Устойчивость карточки |
| Иконка | 4 лота без `faviconUrl` | Текстовая заглушка |
| Длинные строки | 1 лот с длинным названием и описанием | Обрезка без поломки сетки |
| Дата публикации | равномерно за последние 120 дней | Сортировка «сначала новые» |
| Статус | все публичные — `active` | Информационный бейдж |

**Сценарии мок-сервиса** (`localStorage.catalog:mock-scenario`):

| Значение | Эффект на данные | Проверяемый сценарий |
|---|---|---|
| отсутствует | обычная выдача | Базовые сценарии |
| `empty` | `items = []`, `total = 0` | Пустой каталог |
| `error` | промис отклоняется | Ошибка + «Повторить» |
| `slow` | задержка 2000 мс | Скелетоны, гонка ответов |
| `auth-error` | `login()` отклоняется | Ошибка входа (SC-014) |

## 9. Схема связей

```text
CatalogConfig ──bounds/step/pageSize──▶ CatalogFiltersState (draft)
                                              │ apply()
                                              ▼
                                        CatalogFiltersState (applied)
                                              │ + page
                                              ▼
                                        CatalogState ──load()──▶ CatalogResult
                                              │                      │
                                              │                      ├── Listing[]
                                              │                      └── meta
                                              ▼
                                        URL query ──гидратация──▶ CatalogState
DomainZone[] ──варианты фильтра──▶ CatalogFiltersState.zones
Session ──вид правой части шапки──▶ SiteHeader (кнопки входа | аватар)
```

## 10. Правила валидации (сводка)

| Правило | Источник | Где проверяется |
|---|---|---|
| `priceMin ⩽ priceMax`, `incomeMin ⩽ incomeMax` | FR-008, FR-009 | `catalogFilters.normalizeFilters`, слайдеры |
| Границы не отрицательны и не выходят за настройки | FR-008, FR-009 | `clamp` в `catalogFilters` |
| Верхняя граница = «и выше» | clarification, SC-018 | `catalogService.filterListings` |
| `page ≥ 1`, целое | FR-023, FR-028 | `catalogFilters.normalizePage` |
| `page ⩽ lastPage` | edge case | `CatalogState.load` + `router.replace` |
| `perPage = 25` | FR-018 | `CatalogConfig.PAGE_SIZE` |
| Только публичные лоты | FR-017 | `catalogService` (до фильтров) |
| Уникальность `id` и `domain` | SC-004 | фикстуры + тест |
| `zones` только из списка зон | FR-010 | `normalizeFilters` |
| `verifiedOnly` — boolean, по умолчанию `false` | FR-012 | `normalizeFilters` |
| Некорректный URL не вызывает ошибку | FR-028, SC-012 | `useCatalogQuery` + `normalizeFilters` |
