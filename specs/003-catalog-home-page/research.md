# Research: Публичная главная страница с каталогом сайтов

**Feature**: `003-catalog-home-page` | **Date**: 2026-10-28

Спецификация не содержит маркеров `[NEEDS CLARIFICATION]`. Ниже зафиксированы технические решения, необходимые для реализации: интеграция Vue в существующее Laravel-приложение, настройка shadcn-vue без TypeScript, тема Tailwind 4 по референсу, маршрутизация, состояние, мок-слой и стратегия проверки.

---

## 1. Интеграция Vue 3 в Laravel + Vite

**Decision**: Vue 3 монтируется в отдельный Blade-шаблон `resources/views/app.blade.php` с корневым `<div id="app">`. Точка входа — `resources/js/app.js`, которая создаёт приложение, подключает Pinia, роутер и монтирует `App.vue`. `vite.config.js` расширяется плагином `@vitejs/plugin-vue` и алиасом `@` → `resources/js`.

**Rationale**:
- Проект уже использует Vite 8 и Laravel Vite Plugin 3 — отдельный фронтенд-проект и второй сборщик не нужны.
- Один Blade-шаблон обслуживает все SPA-маршруты, поэтому shell-разметка (шапка, meta, `@vite`) описана в одном месте.
- Алиас `@` — обязательное условие генератора shadcn-vue (`@/components/ui/...`).

**Alternatives considered**:
- Отдельный `frontend/`-проект с собственным Vite: дублирует сборку, ломает единый `npm run build`, усложняет деплой.
- Inertia.js: не требуется, страница полностью клиентская, серверного состояния нет.
- Подключение Vue через CDN без сборки: несовместимо с shadcn-vue и Tailwind-токенами.

**Details**:
- `@vitejs/plugin-vue@^6.0.10` поддерживает Vite 8 (peer `vite: ^5 || ^6 || ^7 || ^8`).
- Алиас задаётся ESM-способом: `fileURLToPath(new URL('./resources/js', import.meta.url))`, без `__dirname`.
- Порядок плагинов: `laravel()` → `vue()` → `tailwindcss()`.
- `resources/views/welcome.blade.php` остаётся нетронутым; новый маршрут отдаёт `app.blade.php`.
- CSS подключается через `@vite(['resources/css/app.css', 'resources/js/app.js'])` в shell-шаблоне, поэтому Tailwind сканирует и Blade, и Vue-файлы.

## 2. Версии фронтенд-зависимостей

**Decision**: `vue@^3.5`, `vue-router@^4.6`, `pinia@^3.0`, `@vitejs/plugin-vue@^6.0`, генератор `shadcn-vue@2.9` (CLI). Компоненты shadcn-vue ставятся в проект как исходники и не являются runtime-зависимостью.

**Rationale**:
- `vue-router@4` + `pinia@^3` — зрелая, хорошо документированная связка для Vue 3. `vue-router@5` требует Vue 3.5.34+, Vite 7.3+/8 и объявляет peer-зависимости на `pinia` и `@pinia/colada`, то есть тянет data-loader-слой, который в этой фиче не нужен и увеличивает риск.
- Vue 3.5.44 совместим с `reka-ui` (peer `vue >= 3.4`).
- Фиксация минорных версий в `package.json` защищает от внезапного мажора роутера.

**Alternatives considered**:
- `vue-router@5` + `pinia@4`: новый мажор, лишние peer-зависимости, не даёт функций, нужных каталогу.
- Nuxt: избыточен для одной SPA внутри Laravel, конфликтует с Blade-роутингом и Orchid.
- TypeScript: прямо запрещён требованием заказчика.

## 3. shadcn-vue без TypeScript

**Decision**: инициализация CLI с `components.json`, где `"typescript": false`, `tailwind.css = "resources/css/app.css"`, `baseColor = "neutral"`, `cssVariables = true`, алиасы `@/components`, `@/components/ui`, `@/lib/utils`, `@/composables`. Для разрешения импортов создаётся `jsconfig.json` с `paths: { "@/*": ["./resources/js/*"] }`.

**Rationale**:
- CLI поддерживает JS-вариант компонентов: при `"typescript": false` генерируются `.vue`-файлы без `lang="ts"` и `lib/utils.js` вместо `.ts`.
- Без `jsconfig.json` CLI и IDE не разрешают алиас `@`, и компоненты генерируются с относительными путями или падают на импортах.
- `cssVariables: true` обязателен: тема референса задаётся через CSS-переменные, а не через утилиты в каждом классе.

**Alternatives considered**:
- Ручное копирование компонентов из документации: медленно и приводит к расхождению версий внутренних примитивов `reka-ui`.
- `components.json` с `typescript: true` и последующим удалением типов: грязный дифф, риск синтаксических ошибок.

**Компоненты, которые нужно добавить через CLI**:
`button`, `card`, `slider`, `switch`, `label`, `badge`, `skeleton`, `pagination`, `toggle-group`, `avatar`, `dropdown-menu`, `sheet`, `separator`, `alert`, `sonner`, `tooltip`.

**Обязательные runtime-зависимости компонентов**: `reka-ui`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-vue-next`, `vue-sonner`. Их установит `shadcn-vue add`; версии фиксируются lock-файлом.

## 4. Тема Tailwind 4 по визуальному референсу

**Decision**: палитра из `resources/des/sites-shop_list.html` переносится в `resources/css/app.css` как CSS-переменные shadcn-vue в тёмной схеме (приложение всегда тёмное, переключатель темы не нужен). Дополнительно в `@theme` объявляются брендовые токены (`--color-lime`, `--color-lime-dim`, `--color-surface-*`, `--color-verified`).

| Токен shadcn-vue | Значение | Источник в референсе |
|---|---|---|
| `--background` | `#191a1c` | `--bg-1`, фон страницы |
| `--foreground` | `#e8e9e2` | `--txt-0` |
| `--card` | `#1f2022` | `--bg-2`, карточки |
| `--card-foreground` | `#e8e9e2` | `--txt-0` |
| `--popover` / `--secondary` | `#26272a` | `--bg-3`, панели |
| `--border` | `#2d2e30` | `--line` |
| `--input` | `#3c3d40` | `--line-strong` |
| `--muted-foreground` | `#a8a9a3` | `--txt-1` |
| `--primary` / `--ring` | `#b9c94a` | `--lime` |
| `--primary-foreground` | `#0f1011` | тёмный текст на акценте |
| `--destructive` | `#c5482a` | `--red` |

**Rationale**:
- shadcn-vue ожидает семантические токены; прямая подстановка hex в утилиты привела бы к дублированию цветов и расхождению hover/focus-состояний.
- Тёмная схема — не «опция», а единственный режим референса, поэтому `class="dark"` ставится на `<html>` в shell-шаблоне, а `:root` содержит сразу тёмные значения.
- Лаймовый акцент определён как `--primary`, чтобы кнопки, слайдеры, `Switch` и активные пункты меню автоматически совпадали с референсом.

**Alternatives considered**:
- Tailwind-конфиг в JS: в Tailwind 4 конфигурация живёт в CSS (`@theme`), отдельный `tailwind.config.js` не нужен.
- Светлая тема + переключение: не входит в объём и не соответствует референсу.

## 5. Типографика и форматирование чисел

**Decision**: шрифт Inter (400/500/600/700/800) подключается через `bunny()` в `vite.config.js`, `--font-sans` переопределяется на `Inter` в `app.css`. Числа форматируются `Intl.NumberFormat('ru-RU')`, цена и доход — с суффиксом `₽`, доход — `₽/мес`.

**Rationale**:
- Референс использует `Inter, 'Helvetica Neue', Arial`.
- `Intl.NumberFormat` даёт неразрывные пробелы-разделители разрядов и не ломает вёрстку карточки (FR-022, edge case «очень большие числа»).
- `font-variant-numeric: tabular-nums` на числовых колонках сохраняет выравнивание, как в референсе.

**Alternatives considered**:
- Ручная вставка пробелов: неверные пробелы и отсутствие локализации.
- `Intl.NumberFormat('ru-RU', { notation: 'compact' })`: скрывает точную цену, что критично для лота.

## 6. Маршрутизация и серверная отдача SPA

**Decision**: Vue Router 4 в режиме `createWebHistory()`. Laravel отдаёт shell тремя явными именованными маршрутами:

| Метод | URI | Имя | Ответ |
|---|---|---|---|
| GET | `/` | `catalog` | `app` (shell) |
| GET | `/how-it-works` | `how-it-works` | `app` |
| GET | `/pricing` | `pricing` | `app` |

Vue Router объявляет те же пути: `catalog`, `how-it-works`, `pricing`, плюс клиентский `not-found` (path `/:pathMatch(.*)*`).

**Rationale**:
- Явные маршруты гарантированно не перехватывают `/admin/*`, `/api/*` и `/up`, в отличие от `Route::fallback()` или `Route::get('/{any}')`, которые регистрируются раньше маршрутов Orchid (`config/platform.php`, `prefix = /admin`) и могут «съесть» админку.
- Прямая ссылка и F5 на любой из трёх экранов работают без дополнительной настройки сервера.
- Клиентский 404 покрывает неизвестные пути внутри SPA; серверный 404 на неизвестный deep link — осознанный компромисс этой итерации.

**Alternatives considered**:
- `Route::fallback()` с исключением `admin|api|up`: работает, но зависит от порядка регистрации маршрутов Orchid и от регулярного выражения; риск сломать админку выше выгоды.
- Hash-режим (`createWebHashHistory`): уродливые ссылки `/#/pricing`, ломает требование «поделиться ссылкой».
- Отдельный `routes/spa.php` с префиксом: лишняя сущность для трёх маршрутов.

## 7. Состояние: Pinia + URL как источник восстановления

**Decision**: два стора.
- `catalog` — применённые фильтры, черновик фильтров, страница, размер страницы, элементы, total, loading/error, счётчик запросов для отсечения устаревших ответов.
- `session` — пользователь, статус авторизации, ошибка входа, действия `loginWithVk` / `loginWithYandex` / `logout`.

Синхронизация с адресом — в composable `useCatalogQuery`:
- `route.query` → черновик и применённые фильтры при входе на страницу (гидратация),
- «Применить» → `router.push({ query })`,
- смена страницы → `router.push({ query })`,
- «Сбросить все» → `router.push({ query: {} })`,
- изменения черновика в адрес не попадают.

**Rationale**:
- URL — единственный источник истины для восстановления после F5, копирования ссылки и кнопок «назад»/«вперёд» (FR-027, US4).
- Черновик отделён от применённого набора: до «Применить» список не меняется (FR-014, US1-7).
- `router.push` (а не `replace`) на применение фильтров и смену страницы создаёт записи истории, поэтому «назад» возвращает предыдущий набор фильтров.
- Счётчик запросов решает edge case «быстрое многократное применение»: ответ применяется, только если его номер совпадает с текущим (FR-036).

**Alternatives considered**:
- `localStorage` как источник истины: ломает шаринг ссылок и историю.
- Синхронизация каждого движения слайдера в URL: засоряет историю и вызывает лишние запросы.
- Vuex: устарел, Pinia уже требуется заказчиком.

## 8. Контракт query-параметров URL

**Decision**: канонические имена параметров и правила нормализации.

| Параметр | Тип | Пример | По умолчанию (в URL отсутствует) |
|---|---|---|---|
| `price_min` | целое ≥ 0 | `50000` | `0` |
| `price_max` | целое ≥ 0 | `1200000` | `10000000` (`10 000 000`) |
| `income_min` | целое ≥ 0 | `0` | `0` |
| `income_max` | целое ≥ 0 | `150000` | `1000000` (`1 000 000`) |
| `zones` | CSV зон | `ru,com` | все зоны |
| `verified` | `1` | `1` | выключен |
| `page` | целое ≥ 1 | `2` | `1` |

Правила нормализации (FR-028):
1. Нечисловые, отрицательные или `NaN` значения заменяются значениями по умолчанию.
2. `*_min > *_max` → обе границы меняются на значения по умолчанию.
3. Значения вне фиксированных границ обрезаются по границам.
4. Неизвестные зоны отбрасываются; пустой `zones` = все зоны.
5. `page` нечисловой или `< 1` → `1`.
6. `page > lastPage` → после ответа выполняется `router.replace` на последнюю доступную страницу; ошибка не показывается.
7. Значения по умолчанию в URL не пишутся — ссылка остаётся короткой.

**Rationale**: единый парсер (`lib/catalogFilters.js`) используется и при гидратации, и при записи, поэтому нормализация и сериализация не расходятся.

## 9. Мок-слой данных

**Decision**: сервисный слой с интерфейсом, совпадающим с ожидаемым HTTP-контрактом, и реализацией на фикстурах:

```text
resources/js/services/catalogService.js   → fetchListings(query), fetchZones()
resources/js/services/sessionService.js   → fetchSession(), login(provider), logout()
resources/js/mocks/listings.js            → 63 лота (фикстуры)
resources/js/mocks/zones.js               → начальный набор зон (fallback при ошибке загрузки)
resources/js/mocks/session.js             → гость / демо-пользователь
```

Сервис возвращает `Promise` с задержкой 250 мс, фильтрует, сортирует и пагинирует фикстуры в памяти. `fetchZones()` выводит список зон из публичных фикстур, поэтому новая зона в данных автоматически появляется в фильтре (FR-010); `mocks/zones.js` используется только как fallback при ошибке. Сценарии проверки переключаются ключом `localStorage` `catalog:mock-scenario`:

| Значение | Поведение |
|---|---|
| (нет) | обычная выдача |
| `empty` | пустой каталог (`total = 0`) |
| `error` | ошибка загрузки списка |
| `slow` | задержка 2000 мс для проверки скелетонов |
| `auth-error` | вход через провайдера завершается ошибкой |

**Rationale**:
- Фича фронтендовая (clarification от 2026-10-28), API появится отдельно; сервисный слой — единственная точка замены моков на HTTP-вызовы.
- Сценарии через `localStorage`, а не через query-параметры, чтобы не расширять контракт URL и не конфликтовать с правилом нормализации неизвестных параметров.
- 63 фикстуры (60 публичных) дают три страницы по 25 и позволяют проверить пагинацию, пустые фильтры и «и выше» на верхней границе.

**Alternatives considered**:
- MSW (Mock Service Worker): лишняя зависимость и service worker в Laravel-сборке.
- Статический JSON, отдаваемый Laravel: имитирует API, но противоречит решению «без бэкенда» и требует маршрутов.
- Хардкод данных прямо в компонентах: невозможно протестировать фильтрацию и пагинацию изолированно.

## 10. Мок-авторизация

**Decision**: `sessionService.login(provider)` имитирует OAuth-редирект: задержка 600 мс, затем успешный вход и фикстура пользователя (имя, аватар-инициалы), сохранение в `localStorage` (`catalog:session`) и обновление стора. При сценарии `auth-error` промис отклоняется, показывается тост «Не удалось войти через VK ID. Попробуйте ещё раз», посетитель остаётся на странице с сохранёнными фильтрами. Выход очищает `localStorage`.

**Rationale**:
- Реальный OAuth требует бэкенда, которого нет; при этом UI-контракт кнопок (`@click="loginWithVk"`, `@click="loginWithYandex"`) уже зафиксирован заказчиком.
- Отсутствие навигации при ошибке автоматически выполняет FR-014/SC-014: фильтры не сбрасываются.
- Персистенция в `localStorage` нужна, чтобы аватар сохранялся после F5 и проверялся сценарий «авторизован».

**Alternatives considered**:
- Реальный редирект на `/auth/vk/redirect`: маршрута нет, получим 404 и «сломанную» кнопку.
- Всегда авторизованный демо-пользователь: невозможно проверить состояние гостя и SC-008.

## 11. Обработка загрузки, ошибок и пустых состояний

**Decision**:
- Загрузка: 6 карточек-скелетонов (`Skeleton`) вместо списка; панель фильтров остаётся интерактивной.
- Ошибка: `Alert` с текстом и кнопкой «Повторить», фильтры не сбрасываются.
- Пусто из-за фильтров: `Empty`-блок «Ничего не найдено» + кнопка «Сбросить все».
- Пусто без фильтров: «Предложений пока нет» без кнопки сброса.
- Кнопка «Связаться»: тост sonner «Связь с продавцом появится в следующей версии», без навигации.

**Rationale**: прямо соответствует FR-025, FR-026, FR-029 и edge cases. Скелетоны сохраняют высоту списка и не дают «прыжка» layout.

## 12. Адаптивность и доступность

**Decision**: mobile-first сетка Tailwind. Карточка — строка на `≥lg` (как в референсе) и вертикальная стопка на узких экранах. На `<md` пункты меню уезжают в `Sheet` (гамбургер), кнопки входа показывают только логотипы провайдеров с `aria-label`. Шапка `sticky top-0 z-40` с `backdrop-blur`.

**Rationale**:
- FR-032/SC-010: при 375 px нет горизонтальной прокрутки; перенос меню в `Sheet` — самый предсказуемый способ уложить три пункта и две кнопки.
- FR-033/SC-013: у слайдеров `aria-label` («Минимальная цена», «Максимальная цена») и `aria-valuetext` в рублях, у `Switch` — `Label`, у пагинации — `aria-current="page"` и подписи «Назад»/«Вперёд», фокус-кольцо `ring-ring`.
- Иконки-логотипы VK/Yandex — SVG из референса `cheap-eats`, кнопки сохраняют текстовые подписи на `≥md`.

**Alternatives considered**:
- Горизонтальный скролл навигации: нарушает SC-010 и плохо работает с клавиатуры.
- `DropdownMenu` для меню на мобильном: скрывает текущий раздел и хуже для навигации, чем `Sheet`.

## 13. Стратегия проверки

**Decision**: Vitest 5 + `@vue/test-utils` 2.5 + `jsdom`, отдельный `vitest.config.js`, тесты в `tests/js/**/*.spec.js`.

| Уровень | Что покрывается |
|---|---|
| Юнит | `lib/catalogFilters.js` (нормализация/сериализация query, подсчёт активных фильтров), `lib/format.js` (числа, рубли, нули, большие значения) |
| Юнит (сервис) | `services/catalogService.js`: фильтрация по цене/доходу/зонам/проверке, «и выше» на верхней границе, сортировка «сначала новые», пагинация 25, сценарии `empty`/`error` |
| Стор | `stores/catalog.js`: применение/сброс, сброс страницы на 1, отсечение устаревшего ответа, клампинг страницы |
| Компоненты | `ListingCard` (обязательные поля, «Связаться», нулевая цена, отсутствие описания/иконки), `CatalogFilters` (счётчик, применение, сброс), `CatalogPagination` (диапазон, недоступность «Вперёд») |
| Ручной E2E | `quickstart.md`: фильтры, пагинация, URL, шапка/вход, заглушки, 375 px, клавиатура |

**Rationale**:
- SC-001…SC-018 проверяются либо юнит-тестами (логика), либо чек-листом quickstart (визуал, адаптивность, клавиатура).
- Vitest использует тот же Vite-конфиг и алиасы, поэтому не нужен отдельный транспайлер.
- PHPUnit-наборы не затрагиваются: серверный код в фиче не меняется, кроме трёх маршрутов отдачи shell.

**Alternatives considered**:
- Только ручная проверка: высокая цена регрессий в фильтрации и пагинации.
- Playwright как обязательный набор: ценные E2E-тесты, но требуют отдельного CI-контура; в этой итерации используются как ручной инструмент проверки.
- Jest: хуже интегрируется с Vite 8 и ESM.

**Примечание о зависимостях**: `vue`, `vue-router`, `pinia`, `@vitejs/plugin-vue`, runtime-зависимости shadcn-vue и dev-зависимости тестов добавляются в `package.json`. Это осознанное расширение, требуемое фичей; список фиксируется в `tasks.md`.

## 14. Границы фиксированных диапазонов и «и выше»

**Decision**: конфигурация в `resources/js/lib/catalogConfig.js`:

```js
export const CATALOG_BOUNDS = {
  price:  { min: 0, max: 10_000_000, step: 50_000 },
  income: { min: 0, max: 1_000_000,  step: 5_000 },
}
export const PAGE_SIZE = 25
```

При `priceMax === bounds.price.max` фильтр по цене не ограничивает сверху; то же для `incomeMax`. При значении ниже максимума — включительное сравнение `value <= priceMax`.

**Rationale**:
- Прямо реализует решение из clarification и SC-018: дорогие лоты не теряются в крайнем правом положении.
- Шаг 50 000 ₽ и 5 000 ₽/мес дают по 200 позиций — достаточно точно и удобно с клавиатуры.

**Alternatives considered**:
- Динамические границы по данным: отклонены заказчиком (clarification).
- Расширение `max` до фактического максимума каталога: ползунок теряет смысл при выбросах.
