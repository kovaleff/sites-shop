# Data Model: Вход через VK ID и Yandex ID

**Feature**: `004-vk-yandex-auth` | **Date**: 2026-10-29

Фича не добавляет таблиц и миграций: все необходимые поля уже есть в `users`. Документ фиксирует существующую схему, правила сопоставления аккаунтов, состояние попытки входа и административные фильтры.

Обозначения: `?` — nullable, `→` — производное значение, `⩽` — включительная граница.

---

## 1. Пользователь (`users`)

| Поле | Тип | Nullable | Индекс | Назначение |
|---|---|---|---|---|
| `id` | bigint unsigned, auto increment | нет | PK | Идентификатор аккаунта |
| `name` | varchar(255) | нет | — | Отображаемое имя |
| `email` | varchar(255) | да | UNIQUE `users_email_unique` | Реальный или технический email |
| `email_verified_at` | timestamp | да | — | Не используется в этой итерации |
| `password` | varchar(255) | да | — | Случайное значение для социальных аккаунтов; вход по паролю не предусмотрен |
| `avatar` | varchar(2048) | да | — | Ссылка на фото VK или Яндекса |
| `vk_id` | bigint unsigned | да | UNIQUE `users_vk_id_unique` | Внешний идентификатор VK ID |
| `ya_id` | bigint unsigned | да | UNIQUE `users_ya_id_unique` | Внешний идентификатор Яндекса |
| `vk_last_login_at` | timestamp | да | — | Время последнего успешного входа через VK |
| `ya_last_login_at` | timestamp | да | — | Время последнего успешного входа через Яндекс |
| `remember_token` | varchar(100) | да | — | Механизм «запомнить меня» Laravel |
| `permissions` | json | да | — | Права Orchid |
| `created_at` / `updated_at` | timestamp | да | — | Штатные метки |

**Инварианты**:
- `vk_id` уникален среди непустых значений; `ya_id` — аналогично. Один внешний ID → ровно один аккаунт.
- У аккаунта не более одного `vk_id` и не более одного `ya_id`, но оба могут быть заполнены одновременно (если входы привязались по одному email).
- `email` уникален; технические адреса детерминированы и не пересекаются между провайдерами.
- `email` и `password` могут быть `null`; социальный аккаунт всегда получает `password` (случайный) только из-за схемы.
- `email_verified_at` не заполняется и не проверяется: подтверждение email в эту итерацию не входит (FR-036).

**Массовое заполнение** (`App\Models\User::$fillable`): к унаследованным `name`, `email`, `password`, `permissions` добавляются `avatar`, `vk_id`, `ya_id`, `vk_last_login_at`, `ya_last_login_at`.

## 2. Профиль провайдера (`ProviderProfile`)

Внутренний DTO, не хранится в БД. Создаётся сервисами провайдеров и передаётся в `AccountProvisioner`.

| Поле | Тип | Обязательность | Правила |
|---|---|---|---|
| `provider` | `'vk' \| 'yandex'` | да | Определяет колонку ID, домен технического email и время входа |
| `providerId` | string (цифры) | да | Приводится к целому; `> 0`; уникален в пределах провайдера |
| `name` | string | да | `trim`; при пустом значении — `VK User` / `Пользователь Яндекса` |
| `email` | string \| null | нет | `trim` + `mb_strtolower`; пустая строка → `null`; валидный email; ⩽ 255 символов |
| `avatarUrl` | string \| null | нет | Абсолютный URL; пустая строка → `null`; ⩽ 2048 символов |

**Нормализация по провайдерам**:

| Источник | `name` | `email` | `avatarUrl` |
|---|---|---|---|
| VK (`users.get`, `v=5.131`) | `first_name + last_name`, fallback `VK User` | `email` из ответа обмена кода, если передан | `photo_200` |
| Яндекс (Socialite) | `getName()` → `raw.display_name` → `getNickname()` → `Пользователь Яндекса` | `getEmail()` → `raw.default_email` | `https://avatars.yandex.net/get-yapic/<default_avatar_id>/islands-200`; `null`, если `is_avatar_empty` или id пуст |

## 3. Правила сопоставления аккаунтов

Алгоритм `AccountProvisioner::provision(ProviderProfile $profile): User` выполняется в транзакции:

```text
1. Найти пользователя по колонке провайдера (vk_id / ya_id).
   ├─ найден → обновить профиль и время входа; вернуть.
   └─ не найден → шаг 2.

2. Если email передан:
   ├─ найти пользователя по LOWER(email) с блокировкой строки (lockForUpdate).
   │  ├─ не найден → шаг 3.
   │  ├─ найден, колонка провайдера пуста → привязать ID, обновить профиль; вернуть.
   │  ├─ найден, колонка провайдера равна текущему ID → обновить профиль; вернуть.
   │  └─ найден, колонка провайдера занята другим ID → не перезаписывать; шаг 3 без email.
   └─ email не передан → шаг 3.

3. Создать аккаунт:
   name       = профиль.name
   email      = профиль.email ?? технический адрес
   password   = случайная строка (32 символа)
   <provider>_id = профиль.providerId
   avatar     = профиль.avatarUrl
   <provider>_last_login_at = now()
```

**Обновление существующего аккаунта**:
- `name` перезаписывается актуальным значением.
- `avatar` перезаписывается, если провайдер вернул непустой URL; иначе сохраняется прежний.
- `email` перезаписывается, только если новый email не `null`, отличается без учёта регистра и не занят другим аккаунтом.
- Время последнего входа соответствующего провайдера всегда обновляется.
- Чужая непустая привязка (`vk_id`/`ya_id`) никогда не перезаписывается.

**Технические адреса**:
- VK: `vk<providerId>@vk.users`
- Яндекс: `ya<providerId>@ya.users`
- Детерминированы: повторный вход находит аккаунт по ID, а не по email.
- Домены `.users` не используются для реальной почты и не пересекаются между провайдерами.

**Параллельные запросы**:
- Уникальные индексы `users_vk_id_unique`, `users_ya_id_unique`, `users_email_unique` не дают создать дубль.
- `lockForUpdate()` на найденной по email строке не даёт двум разным ID одновременно привязаться к одному аккаунту: второй запрос увидит занятую привязку и создаст технический аккаунт.
- При `QueryException` выполняется повторный поиск по внешнему ID; если найден — профиль обновляется, иначе исключение пробрасывается.

**Особые случаи**:
- Email совпал с аккаунтом администратора → вход открывает этот аккаунт; в журнал пишется предупреждение `linked_to_admin` (Assumptions).
- Аккаунт с техническим email и последующий вход через второго провайдера с реальным email → отдельный аккаунт, если email не совпал (FR-038).
- Пользователь удалён администратором → следующий вход создаёт аккаунт заново.
- Провайдер не вернул имя/фото → подставляются значения по умолчанию, вход успешен.

## 4. Состояние попытки входа

Попытка — краткоживущее состояние, не таблица.

| Ключ | Где хранится | TTL | Назначение |
|---|---|---|---|
| `state` | сессия (Socialite) | 10 минут | Одноразовое защитное значение Яндекса |
| `ya_oauth_started_at` | сессия | 10 минут | Проверка срока попытки до обмена кода |
| `vk_code_verifier` | cookie (не шифруется) | 600 секунд | PKCE-verifier для обмена кода VK |
| `login_web_<hash>` | сессия | срок сессии | Признак авторизации Laravel |
| `remember_web_<hash>` | cookie | 5 лет (по умолчанию Laravel) | Постоянная сессия «запомнить меня» |
| `_token` | сессия | срок сессии | CSRF-токен |

**Жизненный цикл попытки**:

```text
idle
  └─(нажатие кнопки)→ started: state/verifier/started_at сохранены
        ├─(успех)→ authenticated: пользователь найден/создан, сессия регенерирована,
        │           временные ключи и verifier удалены
        └─(ошибка/отказ/истечение)→ failed: временные ключи удалены,
                                    сессия не меняется, редирект с auth_error
```

**Правила**:
- `state` отклоняется при отсутствии, несовпадении, повторе или возрасте > 10 минут.
- `vk_code_verifier` удаляется после любой попытки обмена.
- Код авторизации и `state` одноразовы; повторное использование отклоняется провайдером/проверкой.
- При любой ошибке незавершённая попытка очищается (FR-033).

## 5. Представление пользователя для SPA

`SessionUserResource` отдаёт единый payload для `GET /api/v1/user`, успешного VK-callback и store:

| Поле | Тип | Правила |
|---|---|---|
| `id` | integer | `users.id` |
| `displayName` | string | `users.name` |
| `email` | string \| null | `users.email`; технический адрес не скрывается |
| `avatarUrl` | string \| null | `users.avatar`; `null` → заглушка в шапке |
| `provider` | `'vk' \| 'yandex' \| null` | Провайдер последнего входа: сравниваются `vk_last_login_at` и `ya_last_login_at`; при равенстве — `vk`; если оба `null` — `null` |

Гостевой ответ: `{ "authenticated": false, "user": null }`.
Авторизованный: `{ "authenticated": true, "user": { ... } }`.

## 6. Административные фильтры и колонки

`App\Models\User` переопределяет унаследованные свойства:

```php
protected $allowedFilters = [
    'id' => Where::class,
    'name' => Like::class,
    'email' => Like::class,
    'vk_id' => Where::class,
    'ya_id' => Where::class,
    'updated_at' => WhereDateStartEnd::class,
    'created_at' => WhereDateStartEnd::class,
];

protected $allowedSorts = [
    'id', 'name', 'email', 'vk_id', 'ya_id',
    'vk_last_login_at', 'ya_last_login_at',
    'updated_at', 'created_at',
];
```

`App\Orchid\Layouts\User\UserListLayout` добавляет:

| Колонка | Фильтр | Сортировка | Отображение |
|---|---|---|---|
| `id` | — | да | Идентификатор аккаунта |
| `vk_id` | `Input::make()` → `Where` | да | Число или `—` |
| `ya_id` | `Input::make()` → `Where` | да | Число или `—` |
| `vk_last_login_at` | — | да | `DateTimeSplit`, скрыта по умолчанию (доступна через переключатель) |
| `ya_last_login_at` | — | да | `DateTimeSplit`, скрыта по умолчанию |

`App\Orchid\Presenters\UserPresenter::image()` возвращает `users.avatar`, если он заполнен, иначе прежний Gravatar. Так аватар провайдера виден в колонке имени.

ID-колонки и VK/Яндекс ID видны по умолчанию; времена входа скрыты по умолчанию, но доступны через переключатель. Колонки не добавляют запросов к БД. Поиск по имени и email сохраняется. Времена последнего входа доступны для сортировки и просмотра.

**Критерий приёмки (SC-009)**: администратор находит пользователя по `vk_id` или `ya_id` через фильтр списка и видит его источник входа не более чем за 30 секунд.

## 7. Связи с существующими сущностями

Социальный вход не меняет связи пользователя:

- `sites` — объявления продавца;
- `conversationsAsBuyer` / `conversationsAsSeller` — диалоги;
- `messages` — сообщения;
- `subscriptionPayments` — платежи;
- роли Orchid (`role_users`).

Аккаунт, созданный провайдером, сразу является полноценным пользователем: отдельный пароль, подтверждение email и дополнительная регистрация не требуются (FR-036).
