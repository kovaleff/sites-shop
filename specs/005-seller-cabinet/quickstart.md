# Quickstart: проверка личного кабинета продавца

**Feature**: `005-seller-cabinet` | **Date**: 2026-10-30

Пошаговая проверка того, что кабинет работает end-to-end. Контракты — [`contracts/cabinet-api.yaml`](./contracts/cabinet-api.yaml) и [`contracts/ui-contract.md`](./contracts/ui-contract.md), данные — [`data-model.md`](./data-model.md).

---

## 1. Предварительные требования

- PHP 8.3, Composer, Node.js 22+, MySQL (или SQLite для локальной проверки).
- Настроенный вход через VK ID/Yandex ID (см. `specs/004-vk-yandex-auth/quickstart.md`) — кабинет доступен только авторизованным.
- Заполненный справочник тематик.

---

## 2. Подготовка

```bash
composer install
npm install

# новые миграции: hidden_at и domain_zone
php artisan migrate

# справочник тематик
php artisan db:seed --class=CategorySeeder

# сборка фронтенда
npm run build
```

Проверить, что появились колонки:

```bash
php artisan tinker --execute 'dump(Schema::getColumnListing("sites"));'
```

Ожидается наличие `hidden_at` и `domain_zone`.

---

## 3. Запуск

```bash
composer run dev
```

Открыть локальный адрес приложения и войти через VK ID или Yandex ID.

---

## 4. Автоматические проверки

```bash
# серверная часть: доступ, валидация, статусы, переписка, каталог
php artisan test --compact tests/Feature/Cabinet tests/Feature/Catalog

# фронтенд: сторы, сервисы, окно «Связаться», форма, бейдж
npm run test

# стиль PHP
vendor/bin/pint --dirty --format agent
```

Ожидается: все тесты зелёные, Pint не вносит изменений. Точечный прогон:

```bash
php artisan test --compact --filter=SiteManagement
```

## 5. Ручные сценарии

### 5.1. Вход в кабинет (US1)

1. Войти на сайт.
2. Нажать на аватар в шапке → «Личный кабинет».
3. **Ожидается**: открылся `/cabinet/sites`, в меню есть «Мои объявления», «Сообщения», «Скрытые».
4. Выйти из аккаунта и открыть `/cabinet/sites` напрямую.
5. **Ожидается**: данные не показаны, появилось сообщение о необходимости входа, пользователь вернулся в каталог.

### 5.2. Создание объявления (US2)

1. В кабинете нажать «Добавить объявление».
2. Отправить пустую форму — **ожидается** подсветка обязательных полей, запись не создана.
3. Заполнить: название, домен `example-check.ru`, описание ≥ 50 символов, цена, доход, выбрать две тематики.
4. Сохранить — **ожидается** переход в список, тост «Объявление создано», карточка со статусом «Активен» и пометкой о неоплаченной подписке.
5. Открыть карточку — **ожидается** имя файла проверки и кнопка копирования.
6. Открыть каталог — **ожидается** отсутствие объявления (подписка не оплачена).
7. Повторить создание с тем же доменом — **ожидается** ошибка «домен уже занят», вторая запись не создана.

### 5.3. Редактирование и статусы (US3)

1. Изменить цену и тематики, сохранить — **ожидается** обновление в списке, имя файла проверки и флаг проверки не изменились.
2. Перевести в «Неактивен», затем «Снят с продажи», затем «Активен» — **ожидается** смена бейджа и исчезновение/появление в каталоге при действующей подписке.
3. Перевести в «Продан» с подтверждением — **ожидается** бейдж «Продан», форма редактирования недоступна.
4. Нажать «Скрыть» — **ожидается** исчезновение из «Мои объявления», появление в «Скрытые»; переписка и платежи сохранены.
5. «Вернуть в список» — **ожидается** возврат карточки в прежнем статусе.

### 5.4. Переписка: покупатель (US5)

1. Войти другим аккаунтом (покупателем).
2. В каталоге у оплаченного объявления нажать «Связаться».
3. **Ожидается** модальное окно с полем сообщения; после отправки — тост, окно закрыто, фильтры и страница каталога не изменились.
4. Открыть `/cabinet/messages` — **ожидается** диалог с продавцом и отправленным сообщением.

### 5.5. Переписка: продавец (US4)

1. Войти продавцом — **ожидается** бейдж непрочитанных на аватаре.
2. Открыть «Сообщения» → диалог — **ожидается** история, сообщение помечено прочитанным, бейдж уменьшился.
3. Ответить — **ожидается** сообщение в треде, диалог поднялся в начало списка.
4. У покупателя открыть диалог — **ожидается** ответ продавца.

### 5.6. Режим только чтения (US4, US5)

1. Сделать объявление неактивным (или дождаться истечения подписки).
2. Открыть диалог обеими сторонами — **ожидается** история видна, поле ввода заблокировано с причиной; отправка недоступна.
3. Вернуть объявление в активное с действующей подпиской — **ожидается** ответы снова доступны, история сохранена.

### 5.7. Подписка (US6)

1. Через Orchid или tinker задать `paid_until` = сегодня + 6 дней.
2. Открыть кабинет — **ожидается** пометка «Требует продления».
3. Задать `paid_until` = сегодня + 8 дней — **ожидается** пометка исчезла.
4. Задать дату в прошлом — **ожидается** пометка сохраняется, объявление отсутствует в каталоге, но остаётся в кабинете.
5. Открыть историю платежей — **ожидается** список платежей или пустое состояние; кнопок оплаты нет.

### 5.8. Чужие данные (FR-015, FR-020)

1. Авторизоваться вторым продавцом.
2. Открыть `/cabinet/sites/{id}/edit` с id чужого объявления — **ожидается** «Объявление не найдено» (404), данные не раскрыты.
3. Открыть `/cabinet/messages/{id}` с чужим диалогом — **ожидается** «Диалог не найден».

### 5.9. Бейдж непрочитанных (FR-032)

1. Отправить сообщение продавцу, находясь на любой странице.
2. Обновить страницу продавца — **ожидается** число на аватаре.
3. Прочитать все сообщения — **ожидается** бейдж исчез.

## 6. Быстрая диагностика

| Симптом | Проверить |
|---|---|
| Кабинет пуст, хотя объявления есть | `hidden`-фильтр списка, `user_id` объявлений |
| «Связаться» возвращает 404 | реальные данные каталога: `GET /api/v1/catalog` непустой, объявление публично видимо |
| 419 при сохранении | наличие `X-CSRF-TOKEN` из `<meta name="csrf-token">` |
| 401 после долгого простоя | сессия истекла — войти заново, данные формы сохраняются |
| Бейдж не обновляется | `GET /api/v1/messages/unread` в Network, `router.afterEach` |
| Зоны пустые | `domain_zone` заполнена у публичных объявлений (бэкфилл миграции) |
| Тесты падают на `domain_zone` | прогнать `php artisan migrate:fresh` в тестовой БД |

---

## 7. Что не входит в проверку

- Приём оплаты и продление подписки (FR-029) — только отображение.
- Внешние уведомления и обновление счётчика в реальном времени.
- Редактирование профиля (имя, аватар, привязка провайдеров).
- Административные действия Orchid (флаг проверки, платежи, справочники) — проверяются существующими тестами `tests/Feature/Orchid`.
