# UI Contract: Оплата подписки через СБП Robokassa

**Feature**: `006-robokassa-sbp-payment` | **Date**: 2026-11-04

Контракт описывает экраны кабинета, публичной страницы «Тарифы» и админки, их состояния и связь с FR спецификации. API-контракт — [`cabinet-payments-api.yaml`](./cabinet-payments-api.yaml), данные — [`data-model.md`](../data-model.md).

---

## 1. Маршруты

| Маршрут | Тип | Назначение | Доступ |
|---|---|---|---|
| `/cabinet/sites` | SPA (существует) | Список объявлений с действием «Продлить»/«Продолжить оплату» и окном оплаты | Авторизованный продавец |
| `/pricing` | SPA (существует) | Публичные цена, сроки и скидки | Все |
| `/admin/marketplace/subscription-settings` | Orchid (новый) | Настройки тарифа | Право `platform.marketplace.subscription-settings` |
| `/admin/marketplace/payments` | Orchid (существует) | Список всех платежей с фильтрами и сортировкой | Право `platform.marketplace.payments` |
| `/admin/marketplace/payments/{id}` | Orchid (существует) | Карточка платежа и разбор «Требует проверки» | Право `platform.marketplace.payments` |

Отдельный SPA-маршрут карточки объявления не вводится: оплата и история открываются модальным окном из `SiteCard`, чтобы не дублировать форму редактирования.

## 2. Кабинет: карточка объявления (`SiteCard.vue`)

### 2.1. Действия

| Условие | Кнопка | Поведение |
|---|---|---|
| `status` = `active`, `inactive`, `withdrawn`; нет открытой попытки | «Продлить» | Открывает `PaymentDialog` на шаге формы |
| Есть `latestPayment.status` = `pending` и QR не истёк | «Продолжить оплату» | Открывает `PaymentDialog` сразу на шаге QR (через `POST /start`) |
| `latestPayment.status` = `failed` или `cancelled` | «Повторить» | Открывает форму новой попытки |
| `latestPayment.status` = `requires_review` | «Платёж на проверке» | Открывает историю с пояснением; новая оплата недоступна |
| `status` = `sold` | Кнопки оплаты нет | Прямой запрос API → 422 `sold` |
| Гость/чужое объявление | — | API → 401/404; данные не раскрываются |

### 2.2. Отображение подписки

- `SubscriptionBlock` показывает `paid_until` («Оплачено до …» или «Подписка не оплачена»), «Требует продления» (7 дней) и «Скрыто из каталога».
- После успешной оплаты блок обновляется из ответа `GET /my/payments/{id}` или повторной загрузки списка; полная перезагрузка страницы не требуется (FR-023, FR-033).
- Если `latestPayment` есть, рядом с датой показывается статус последней попытки (маленький бейдж) и ссылка «История».

## 3. Окно оплаты (`PaymentDialog.vue`)

### 3.1. Шаги и состояния

| Состояние | Что видит продавец | Действия |
|---|---|---|
| `loading-options` | Skeleton, заголовок «Продление подписки» | Закрыть |
| `form` | Базовая цена за месяц, выбор срока (1/3/6/12), скидка, итог, email для чека, целевой статус, предупреждение о скрытии | Выбрать срок, изменить email, «Перейти к оплате», закрыть |
| `creating` | Кнопка «Создаём счёт…», поля заблокированы | — |
| `qr` | QR-код СБП, ссылка «Открыть в банковском приложении», таймер, сумма, срок, email, «Проверить статус» | Открыть ссылку, проверить, закрыть, «Создать новую попытку» после истечения |
| `polling` | Тот же QR + «Ожидаем подтверждение…», `aria-live` | Проверить вручную, закрыть |
| `success` | «Оплата получена», новая дата «оплачено до», целевой статус, кнопка «Готово» | Закрыть, перейти к объявлению |
| `failed` | Причина, «Повторить» | Создать новую попытку |
| `cancelled` | «Срок действия QR истёк»/«Создана новая попытка», «Повторить» | Создать новую попытку |
| `review` | «Платёж на проверке», причина, «История» | Закрыть, открыть историю |
| `error` | Понятный текст ошибки, «Повторить» | Повторить запрос |

### 3.2. Форма

- Сроки приходят из `PaymentOptions.periods`; по умолчанию выбран 1 месяц. Скидка показывается отдельной строкой, итог — крупно, цена за месяц — справочно.
- Email: предзаполнен `defaultReceiptEmail`; если `hasDeliverableEmail = false`, поле пустое и обязательное, с подсказкой «Укажите email для чека».
- Целевой статус: «После оплаты объявление станет: Активен/Неактивен». Если `willBeHidden = true`, показывается предупреждение: «Объявление останется скрытым из каталога. Вы сможете включить его в кабинете».
- Если `canPay = false`, форма не показывается; выводится `blockedMessage` (проданное объявление, платёж на проверке, тариф отключён, конфликт домена, нужен email).
- Сумма не редактируется; при изменении цены/скидки на сервере (422) показывается новое значение и требуется повторное подтверждение.

### 3.3. QR и polling

- После `POST /payments` фронтенд динамически загружает `robokassa.scriptUrl` и вызывает `Robokassa.pay.startOp`. Контейнер QR — `#robokassa-qr-container`; размер — 320 px (на мобильном — 260 px).
- Если скрипт не загрузился или `startOp` выбросил ошибку: показывается «Не удалось получить QR. Проверьте соединение и попробуйте снова», счёт остаётся `pending` до TTL; повторный вызов `POST /start` возвращает те же параметры.
- Polling: `usePaymentPolling` опрашивает статус каждые 4 с; пауза при `document.hidden`; возобновление на `visibilitychange`; backoff 4 → 8 → 15 с при сетевых ошибках; остановка на `paid`/`failed`/`cancelled`/`requires_review`.
- Таймер показывает оставшееся время; по истечении — состояние `cancelled`, QR скрывается, кнопка «Создать новую попытку».
- Ссылка на оплату всегда доступна текстом и кнопкой, даже если QR не отрисовался (FR-011).

### 3.4. Доступность и локализация

- `role="dialog"`, `aria-modal="true"`, заголовок через `aria-labelledby`; фокус переходит на первый элемент, Esc закрывает (с подтверждением, если идёт оплата).
- Статус оплаты объявляется через `aria-live="polite"`; таймер не является единственным носителем информации.
- QR имеет текстовое описание и ссылку; все действия доступны с клавиатуры.
- Все подписи и сообщения — на русском; месяцы склоняются («1 месяц», «3 месяца», «12 месяцев»); суммы форматируются через `formatRub`.

## 4. История платежей (`PaymentHistory.vue`)

| Элемент | Правило |
|---|---|
| Сортировка | От новых к старым |
| Поля | Номер счёта, сумма, срок, способ «СБП», статус, базовая цена, скидка, дата создания, дата оплаты, причина |
| `pending` | «Продолжить оплату», если QR действует; иначе «Создать новую попытку» |
| `failed` | Причина + «Повторить» |
| `cancelled` | Причина (истёк QR / новая попытка / продажа) + «Повторить» |
| `requires_review` | «Платёж на проверке», причина, без кнопки оплаты |
| `paid` | Дата оплаты, сумма, срок; без действий |
| Старые записи | Если новых полей нет — показываются сумма, срок, статус, дата; без «—» в критичных местах |
| Пусто | «Платежей ещё не было» |

История загружается `GET /my/sites/{site}/payments` при открытии окна/секции; ошибка — «Не удалось загрузить историю» + «Повторить».

## 5. Публичная страница «Тарифы» (`PricingView.vue`)

- Загружает `GET /api/v1/pricing`; состояния: skeleton, ошибка с повтором, пусто/неактивный тариф.
- Показывает базовую цену за месяц, карточки сроков с процентом скидки, итогом и ценой за месяц; для 1 месяца скидка не показывается.
- Если `isActive = false`: «Оплата временно недоступна» и пояснение, что цена настраивается; кнопка ведёт в кабинет.
- CTA: «Перейти в кабинет» для авторизованных, «Войти» для гостей; ссылка на кабинет не раскрывает чужие данные.
- Данные обновляются не дольше чем за 1 минуту после изменения в админке (кеш 60 с).

## 6. Админка: настройки тарифа

`SubscriptionSettingScreen`:

| Поле | Контрол | Валидация/подсказка |
|---|---|---|
| Базовая цена за домен в месяц | `Input` (number, step 0.01) | > 0; копейки допустимы |
| Доступные сроки | `Select` multiple / чекбоксы 1, 3, 6, 12 | Обязательно 1; уникальные; 1–24 |
| Скидка для 3 месяцев | `Input` number 0–99 | Целое; итог > 0 |
| Скидка для 6 месяцев | `Input` number 0–99 | Целое; итог > 0 |
| Скидка для 12 месяцев | `Input` number 0–99 | Целое; итог > 0 |
| Целевой статус после оплаты | `Select` «Активен»/«Неактивен» | По умолчанию «Активен» |
| Срок действия QR, мин | `Input` number 1–60 | По умолчанию 15 |
| Тариф активен | `Switcher` | Выключен — новые счета не выставляются |

- Сохранение: валидация, `SubscriptionSetting::current()->update(...)`, сброс кеша, тост «Настройки сохранены».
- Ошибка: сообщение у поля, введённые значения не теряются.
- Рядом — пояснение: «Изменения применяются только к новым счетам. Уже выставленные счета сохраняют прежние условия».

## 7. Админка: платежи

### 7.1. Список

| Колонка | Содержимое |
|---|---|
| Счёт | `invoiceNumber` (ссылка на карточку) |
| Объявление | `site_domain` (снимок) + текущий домен, если отличается |
| Плательщик | Имя/email |
| Сумма | Итог, рубли; справочно — базовая цена и скидка |
| Срок | `periodMonths` |
| Статус | Бейдж с подписью |
| Способ | «СБП» / «—» |
| Тест | «Тест» / пусто |
| Создан | Дата/время |
| Оплачен | Дата/время |

Фильтры (панель `Selection`):
- Домены — текстовое поле, несколько значений через запятую/пробел/перенос; ищет по снимку и текущему домену.
- Статус — мультивыбор пяти статусов.
- Дата оплаты — диапазон start/end.
- Способ — `СБП` / `—`.
- Номер счёта — числовой поиск.
- Плательщик — имя/email.
- Объявление — домен/название (существующий фильтр).

Сортировка: по умолчанию `created_at desc`; переключатели для `created_at`, `paid_at`, `amount`. Пустой результат — «Платежи не найдены» с кнопкой сброса фильтров.

### 7.2. Карточка платежа

- Снимок: номер счёта, домен на момент счёта, текущий домен, плательщик, email для чека, базовая цена, скидка, итог, срок, целевой статус, способ, тест, QR-срок, дата создания/оплаты.
- Провайдер: `provider`, `external_id`, `provider_payload` (без подписи), причина проверки.
- История решений: администратор, дата, «Принят»/«Отклонён», комментарий.
- Для `requires_review`: форма «Решение» (`Select` принять/отклонить), `TextArea` комментарий (обязательно, 5–2000), кнопка «Сохранить решение». После успеха — тост и обновлённый статус; после ошибки — сообщение, статус не меняется.
- Для `paid`/`failed`/`cancelled` форма скрыта; показывается объяснение, что изменение невозможно.

## 9. Тексты ошибок (продавец)

| Код | Текст |
|---|---|
| `sold` | Проданное объявление нельзя оплатить. |
| `under_review` | Предыдущий платёж ещё проверяется. Дождитесь решения администратора. |
| `tariff_inactive` | Оплата временно недоступна. Попробуйте позже. |
| `domain_conflict` | Домен уже занят другим активным или неактивным объявлением. Измените домен или обратитесь в поддержку. |
| `receipt_email_required` | Укажите email для чека. |
| `invalid_period` | Выберите срок из доступных. |
| `invalid_amount` | Итоговая сумма должна быть больше нуля. Проверьте настройки тарифа. |
| `expired` | Срок действия QR-кода истёк. Создайте новую попытку. |
| `provider_unavailable` | Не удалось получить QR-код. Проверьте соединение и повторите попытку. |
| `not_payable` | Платёж больше нельзя продолжить. Создайте новую попытку. |

Технические детали (stack trace, ответ провайдера, подпись) в интерфейс не попадают.
